- **Tâche 4 — compatibilité MV2 et journal** : `src/main/extensions/{stubs,journal}.ts`, `resources/extensions/{shim-head,shim-post}.js`.
  - `stubs.ts` : `appliquerStubs(dossier, manifest, shims)` (MV2 seulement ; marqueur `lyra-stubs.json`, idempotent) copie `lyra-shim-head.js` / `lyra-shim-post.js` à la racine, les place dans `background.scripts` (head avant le polyfill, post juste après ; sans polyfill, les deux en tête) et dans les pages HTML (arrière-plan, popup, options, devtools, remplacements). Appelé par `finaliser` (toutes les sources : cws, crx, zip, dossier, ubo, amo, xpi) et par le chargeur (`avantChargement`) pour les extensions déjà installées sans marqueur. MV3 : rien.
  - Shims : proxys inertes pour `browserAction`, `pageAction`, `action`, `contextMenus`, `menus`, `webNavigation`, `privacy`, `windows`, `commands`, `dns`, `notifications`, `declarativeNetRequest`, seulement si l'API manque dans `chrome.*` ; appel = callback ou promesse résolus sans effet + compteur `globalThis.__lyraStubs["pageAction.show"]`.
  - **Constats Electron 44 / electron-chrome-extensions 4.9 (à connaître)** : (1) `chrome` est **gelé** (l'extension d'Electron fait `Object.freeze(chrome)`), l'affectation est silencieusement sans effet : `shim-head` remplace alors `globalThis.chrome` par un accesseur qui rend un proxy (délègue à l'objet courant, stub seulement pour l'API absente) ; (2) Chromium définit un `browser` natif **sans** les API d'electron-chrome-extensions (`browserAction`, `contextMenus`, `windows`…) et uBlock Origin fait `self.chrome = self.browser` : c'est la vraie cause du plantage `setBadgeBackgroundColor` du spike. `shim-post` recopie donc dans `browser.*` toute clé de `chrome.*` absente (API natives d'ECE incluses, pas seulement les stubs), avec repli proxy si `browser` est gelé. Conséquence : `browserAction` est natif dans Lyra (jamais stubé, donc jamais compté) ; les stubs comptés sont en pratique `pageAction`, `menus`, `dns`, `action`…
  - Comptage : une extension ne peut pas parler au processus principal ; `journal.ts` lit `globalThis.__lyraStubs` par `webContents.executeJavaScript` sur chaque page `chrome-extension://<id>/` (arrière-plan, popup, options) à la demande (`extensions:journal`) et toutes les 5 s ; seule la différence avec le relevé précédent de la page est ajoutée (page rechargée = nouveau total). Un MV3 (service worker) n'a pas de stubs, donc rien à relever.
  - `journal.ts` : `userData/extensions/journal/<id>.json` (écriture atomique tmp + rename) `{ avertissementsChargement, apiStubees, apiManquantes, conflitsRaccourcis, redondanceBoucliers, noteBoucliers, conversion? }`. Avertissements : message MV2 abandonné + `console-message` warning/error des pages d'extension (`app.on('web-contents-created')`). `apiManquantes` : permissions / `optional_permissions` / clés `commands`, `side_panel` dans une liste prudente (`declarativeNetRequest*`, `sidePanel`, `nativeMessaging`, `fontSettings`, `theme`, `contextualIdentities`, `commands`, `tabGroups`, `identity`, `proxy`…). `redondanceBoucliers` si `webRequest` ou `webRequestBlocking` → « blocage réseau assuré par les Boucliers ». Conflits de raccourcis : même `suggested_key` que l'une des autres extensions actives. `conversion` = `lyra-conversion.json` de la tâche 3. Supprimé avec la désinstallation. IPC `extensions:journal { id }`.
  - Tests : `stubs.test.ts` (contexte `vm` : stubs, `chrome` figé, `browser` figé avec `chrome = browser`, MV3 sans stub, idempotence, pages et scripts), `journal.test.ts`, ajouts à `chrome.installation.test.ts` et `chargeur.test.ts` ; e2e `extensions-mv2.spec.ts` (zip MV2 réduit : démarre, `pageAction.show` ×2, `menus.create`, `dns.resolve` comptés, redondance) ; `@reseau` : uBO (release GitHub) sans erreur de console ni `TypeError`, journal avec redondance ; `youtube.spec.ts` rejoué avec uBO chargé (aucune pub, les Boucliers priment).
  - Limite connue : une page d'uBO non listée dans le manifest (ex. `about.html`) n'a pas les shims ; `browser` natif sans ECE n'y est pas complété.

# Lyra — plan du jalon B : extensions Chrome et Firefox

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax. Branche `jalon-b` (worktree `lyra.worktrees/jalon-b`), fusionnée dans `main` par la session principale à la fin. Avancement tenu dans `docs/superpowers/etat-jalon-b.md`.

**Goal:** installer, charger, mettre à jour et journaliser des extensions Chrome (Chrome Web Store, `.crx`, `.zip`, dossier) et Firefox (addons.mozilla.org, `.xpi`, converties en extension Chromium avec le polyfill `browser.*`), avec une couche de compatibilité MV2, des icônes d'action dans le pied du ciel, une page `lyra://extensions` conforme au design, et une fonction d'installation par identifiant que le jalon E réutilise pour `import.extensionsEnAttente`. Critère d'acceptation v1 (spec §9, réponse 5) : Dark Reader fonctionnel depuis le Chrome Web Store **et** depuis AMO (converti) ; uBlock Origin (Chrome MV2 depuis sa release GitHub, et xpi converti) démarre et journalise la redondance webRequest ; Return YouTube Dislike converti MV2→MV3 ; Tree Style Tab refusé avec motif.

**Spec:** `docs/superpowers/specs/2026-10-19-lyra-design.md` §7 (Extensions : ce qui marche, règle fondatrice « les Boucliers priment », Chrome, Firefox, tests, limites honnêtes) et §9 réponses 4 (popups natifs d'electron-chrome-extensions), 5 (périmètre Firefox), 6 (Boucliers ignorent `chrome-extension://`), 8 (mises à jour toutes les 6 h, désactivables). **Spike (code de référence, pas du code produit) :** `docs/superpowers/spikes/extensions/` (`main.js`, `convert.js`, `shim-head.js`, `shim-post.js`, `logs/`). **Recherche :** `docs/superpowers/research/2026-10-19-electron-et-firefox-extensions.md` et `2026-10-19-electron-chrome-extensions.json`. **Design (fait foi) :** `docs/design/project/Extensions.dc.html` (en-tête « Extensions — Chrome et Firefox, côte à côte / Ce qui ne marche pas est dit, pas caché », « Tout mettre à jour », « Vérifiées il y a 2 h », trois cartes d'installation Chrome / Firefox / Fichier, liste « Installées — n » avec boutons Options · Sites · Journal, mentions « s'ajoute aux Boucliers, ne les remplace pas », « Firefox · convertie », « 2 fonctions Firefox ignorées », bloc des limites).

## Global Constraints
- **Aucune fenêtre visible** (consigne impérative de l'utilisateur) : tests e2e et captures uniquement via la config Playwright (`LYRA_TEST=1` → fenêtres cachées, `src/main/modeTest.ts`) ; jamais `LYRA_E2E_VISIBLE`, jamais `npm run dev`, jamais l'app empaquetée à l'écran. Toute nouvelle fenêtre ou vue (popup d'extension, page d'options, fenêtre créée par `createWindow`) passe par `optionsFenetreCachee()` / `prefsPageCachee()` sous `LYRA_TEST`.
- Respect strict du design validé (valeurs, libellés, icônes copiées de `Extensions.dc.html`).
- Dépendances : `electron-chrome-extensions` (GPL-3.0, licence déclarée dans le constructeur), `electron-chrome-web-store`, `webextension-polyfill` (copié dans `resources/extensions/browser-polyfill.js`), une bibliothèque zip pure JS (`fflate` ou `yauzl`) ; pas de module natif. Electron reste en 44.x tant que le MV2 des extensions clés en dépend.
- **Les Boucliers priment** : Lyra garde son listener `session.webRequest` ; une extension bloqueuse s'installe mais son blocage réseau est inopérant et le journal le dit. Le filtrage des Boucliers ignore les requêtes dont l'initiateur ou l'URL est `chrome-extension://` et le protocole CRX (`src/main/shields/Shields.ts`, ajout localisé).
- Les extensions ne sont chargées que sur `persist:lyra` ; jamais en fenêtre privée (limite d'electron-chrome-extensions, dite dans `lyra://extensions`).
- Réseau : Chrome Web Store, AMO et les releases GitHub de uBO sont les seules destinations ; sha256 d'AMO vérifié avant extraction ; cache local par version sous `userData/extensions/cache` ; téléchargements refusés en fenêtre privée.
- Sécurité des archives : extraction sans traversée de chemin (`..`, chemins absolus, liens), taille décompressée bornée (128 Mio), manifest validé avant chargement ; un dossier `userData/extensions/<id>/<version>/` par version, suppression atomique à la désinstallation.
- Fichiers partagés avec C/E (`src/main/index.ts`, `src/renderer/ui/Capsule.tsx`, `src/shared/ipc.ts`, `src/main/settings/{defaults,validate}.ts`, `package.json`) : ajouts localisés seulement.
- Machine Windows à mémoire basse : vitest `--no-file-parallelism`, un seul e2e à la fois. Ne jamais lire les vrais profils ni les vraies extensions de l'utilisateur.
- Commits en français terminés par `Claude-Session: https://claude.ai/code/session_014rF1oHCSDeDLpfg5ceCFns` ; push de `jalon-b` après chaque commit.

## Review Focus
1. Une extension MV3 installée depuis le Chrome Web Store (Dark Reader) est rechargée à chaque démarrage **avant** la création des vues, dans l'ordre d'installation, et agit sur une page (`style.darkreader` présent) ; désactivée dans les réglages, elle n'est plus chargée au démarrage suivant.
2. uBlock Origin MV2 (release GitHub) démarre sans erreur grâce aux stubs ; chaque API stubée appelée est comptée dans le journal ; le journal affiche « blocage réseau assuré par les Boucliers » ; ses filtres cosmétiques restent actifs ; les Boucliers bloquent toujours YouTube (test `@youtube` inchangé).
3. Convertisseur xpi : Dark Reader (xpi) fonctionne ; Return YouTube Dislike MV2→MV3 charge (`background.sw.js`, CSP objet, `web_accessible_resources` en tableau d'objets, hôtes dans `host_permissions`) ; Tree Style Tab est refusé avec le motif « `sidebar_action` seul moyen d'interaction » ; le rapport JSON liste chaque clé et permission retirée.
4. Archives hostiles : zip avec `../`, chemin absolu, 10 000 fichiers ou 1 Gio annoncé → refus propre, rien d'écrit hors du dossier cible, aucune exception non gérée ; `.crx` sans en-tête CRX3 valide → refus.
5. `installerParId({ id, nom, magasin })` (jalon E) : `chrome` installe depuis le Chrome Web Store, `firefox` depuis AMO, `edge` et `inconnu` sont mis en « à installer à la main » avec explication ; une file de 5 IDs s'installe en série, une erreur n'arrête pas les suivantes, chaque résultat est journalisé.
6. Aucune fenêtre visible pendant les tests : les popups et pages d'options créés par electron-chrome-extensions passent par les options cachées sous `LYRA_TEST`.

### Task 1 : noyau de chargement et registre des extensions
`src/main/extensions/{Extensions,registre,chargeur}.ts` : `Extensions` (singleton du processus principal) instancie `ElectronChromeExtensions({ license: 'GPL-3.0', session: persist:lyra, createTab, selectTab, removeTab, createWindow, removeWindow, requestPermissions, assignTabDetails })` branché sur `TabManager`/`WindowManager` (`addTab(webContents, window)` à chaque étoile créée, retrait à la fermeture ; `createWindow` → `WindowManager.creerFenetre`, cachée sous `LYRA_TEST`), `ElectronChromeExtensions.handleCRXProtocol(session)`. Registre `settings.extensions.installees[]` (`{ id, nom, version, source: 'cws'|'crx'|'zip'|'dossier'|'amo'|'xpi', magasin: 'chrome'|'edge'|'firefox'|'inconnu', dossier, active, installeeLe, miseAJourLe, convertie?: boolean }`, validé dans `settings/validate.ts`, valeurs par défaut dans `defaults.ts`) ; `chargeur.ts` charge au démarrage (`session.extensions.loadExtension(dossier, { allowFileAccess: false })`, ordre d'installation, extensions actives seulement, avant la création des vues dans `index.ts`), désactive/réactive à chaud (`removeExtension`/`loadExtension`), désinstalle (retrait + suppression du dossier). Les Boucliers ignorent `chrome-extension://` et CRX (`Shields.ts`). IPC `extensions:lister/activer/desinstaller` (`shared/ipc.ts`, origines vérifiées dans `ipc-origines.ts`). Tests : vitest sur le registre (validation, migration d'un `settings.json` sans section), chargeur avec une extension de fixture minimale MV3 (`src/main/extensions/fixtures/minimale-mv3/`) ; e2e `tests/e2e/extensions.spec.ts` : l'extension de fixture (chargée via `LYRA_EXTENSIONS_FIXTURES`) injecte un marqueur dans une page, puis n'est plus chargée une fois désactivée.

### Task 2 : installation Chrome (Web Store, `.crx`, `.zip`, dossier) et mises à jour
`src/main/extensions/{chrome,archives,miseAJour}.ts` : `installerChrome(source)` avec `source` = ID (32 lettres a-p) ou URL du Chrome Web Store (`installExtension(id, { session, extensionsPath })` d'`electron-chrome-web-store`, `minimumManifestVersion` 2, `beforeInstall` qui refuse les thèmes), fichier `.crx` (en-tête CRX3 lu, retiré → zip), `.zip`, dossier décompressé (copié) ; `archives.ts` : extraction zip pure JS sûre (traversée, taille bornée, liens ignorés) + lecture CRX3 ; **uBO** : source spéciale `ubo` = dernière release GitHub `uBlock0_<v>.chromium.zip` (le Chrome Web Store répond 204, spec §7) ; `miseAJour.ts` : `updateExtensions` au démarrage puis toutes les 6 h (désactivable, réglage dans « Réseau et identité »), bouton « Tout mettre à jour », horodatage « Vérifiées il y a … ». **Fonction d'installation par ID pour le jalon E** : `installerParId({ id, nom, magasin }): Promise<ResultatInstallation>` (`chrome` → Web Store ; `firefox` → Task 3 ; `edge`/`inconnu` → `{ etat: 'manuel', raison }`) et `installerFile(liste, surProgression)` qui consomme `import.extensionsEnAttente` en série sans s'arrêter sur une erreur. Tests : vitest sur CRX3 (fixture octet par octet), extraction (zip de fixture sain + 4 hostiles), analyse d'ID/URL, `installerFile` avec un installateur simulé ; e2e réseau `@reseau` : Dark Reader depuis le Chrome Web Store → `style.darkreader` sur une page de test (fenêtres cachées).

### Task 3 : Firefox — téléchargement AMO et convertisseur `xpi → dossier`
`src/main/extensions/{firefox,convertisseur,amo}.ts` : `amo.ts` (API v5 `addons/addon/<slug>` → `current_version.file.url` + `hash` sha256, vérifié avant extraction ; cache par version ; nom ou URL AMO acceptés) ; `convertisseur.ts` réglé et **auditable** (rapport JSON `{ cles_retirees, permissions_retirees, transformations, avertissements, refus? }`) : extraction, suppression de `META-INF/`, `browser_specific_settings`/`applications` retirés, `menus`→`contextMenus`, permissions Firefox-only retirées et journalisées (`dns`, `theme`, `contextualIdentities`, `find`, `pkcs11`, `captivePortal`, `browserSettings`, `tabHide`, …), clés `sidebar_action`, `theme_experiment`, `experiment_apis`, `protocol_handlers`, `user_scripts`, `developer`, `browser_style` retirées ; `_execute_browser_action`→`_execute_action` ; MV2 : `background.scripts`/`page` conservés, `persistent: true` ; MV3 : `background.scripts` → `background.sw.js` (`importScripts`), CSP chaîne → `{ extension_pages }`, `web_accessible_resources` → `[{ resources, matches }]`, hôtes → `host_permissions` ; `browser-polyfill.js` (puis stubs MV2 de la Task 4) ajouté en tête des scripts d'arrière-plan, des content scripts et des pages HTML (popup, options, overrides) ; icônes SVG → PNG (via une `BrowserWindow` cachée ou `nativeImage`) ; **refus motivé** si `sidebar_action` est le seul moyen d'interaction ou si `experiment_apis` est présent ; suggestion « version Chrome disponible » quand le même nom existe sur le Chrome Web Store (liste courte embarquée : Bitwarden, Dark Reader, uBO, RYD…). `installerFirefox(source)` = AMO ou `.xpi`, puis chargement comme une extension Chrome (`convertie: true`). Tests : vitest sur des manifests de fixture (`fixtures/manifests/{ubo-ff,dark-reader-ff,bitwarden,tree-style-tab,ryd-mv2}.json`) → rapport attendu, refus de Tree Style Tab, MV2→MV3 de RYD, polyfill en tête ; e2e réseau `@reseau` : Dark Reader depuis AMO converti → `style.darkreader`.

### Task 4 : couche de compatibilité MV2 et journal de compatibilité
`src/main/extensions/{stubs,journal}.ts` + `resources/extensions/{shim-head,shim-post}.js` (généralisés depuis le spike) : stubs inertes (`browserAction`, `contextMenus`, `webNavigation`, `privacy`, `windows`, `commands`, `dns`, …) injectés en tête des scripts d'arrière-plan et des pages de l'extension **uniquement** quand le manifest est MV2 et que l'API manque dans `chrome.*` (proxys avant le polyfill, recopiés dans `browser.*` après) ; chaque appel stubé envoie `chrome.runtime`→processus principal un événement compté (« API ignorée : browserAction.setBadgeText ») ; `journal.ts` par extension : avertissements de chargement (permissions inconnues d'Electron), API stubées appelées (comptées), API manquantes (`declarativeNetRequest`, `commands`, `sidePanel`, `nativeMessaging`…), conflits de raccourcis, « blocage réseau assuré par les Boucliers » pour toute extension qui déclare `webRequestBlocking` ou `webRequest`, et pour une convertie les clés/permissions retirées (rapport de la Task 3) ; persistance `userData/extensions/journal/<id>.json`, IPC `extensions:journal`. Tests : vitest sur les stubs dans un contexte simulé (`vm`) — un MV2 sans `browserAction` ne plante plus, un MV3 ne reçoit aucun stub, comptage ; e2e : uBO (zip de fixture réduit ou release GitHub en `@reseau`) démarre sans erreur dans la console du background et le journal contient la redondance webRequest ; test `@youtube` toujours vert avec uBO chargé.

### Task 5 : page `lyra://extensions`, icônes d'action, popups et options
`src/renderer/extensions/` (Preact, portage fidèle d'`Extensions.dc.html`) servie par le protocole `lyra://` : en-tête, bouton « Tout mettre à jour » + « Vérifiées il y a … », cartes d'installation Chrome (« Identifiant ou adresse du Chrome Web Store »), Firefox (« Nom ou adresse addons.mozilla.org »), Fichier (« Choisir… », `.crx`/`.zip`/`.xpi`/dossier via dialogue natif, caché sous `LYRA_TEST` = chemin injecté) ; liste « Installées — n » : nom, version, origine (« Chrome », « Firefox · convertie »), portée (« Tous les sites », « Tous les sites sauf youtube.com (règle par site) »), état (« fonctionne ; 2 fonctions Firefox ignorées », « s'ajoute aux Boucliers, ne les remplace pas »), interrupteur, boutons **Options** (page d'options en nouvelle étoile), **Sites** (règle par site : `settings.sites[origine].extensions[id] = false`, appliquée en retirant les content scripts par site si l'API le permet, sinon désactivation documentée), **Journal** (panneau du journal de la Task 4), Désinstaller ; bloc « Limites » (texte des limites honnêtes de la spec §7). Icônes d'action dans le pied du ciel : `injectBrowserAction()` dans `src/preload/ui.ts`, `<browser-action-list>` dans `Sky.tsx`/`Capsule.tsx` (ajout localisé), popups = mécanisme natif d'electron-chrome-extensions (§9 réponse 4), `BrowserWindow` cachée sous `LYRA_TEST`. Entrée « Extensions » dans le menu ⋯ et la palette (`lyra://extensions`). Tests : e2e `extensions.spec.ts` (page rendue avec la liste, installation d'un `.zip` de fixture par chemin injecté, interrupteur, journal affiché, désinstallation) ; captures en fenêtre cachée comparées aux libellés du design.

# Lyra — jalon E, Task 3 : application dans Lyra (plan détaillé)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax. Branche `jalon-e` (worktree `lyra.worktrees/jalon-e`). Ce document détaille la Task 3 du plan `2026-10-19-lyra-jalon-e.md` ; les Tasks 1 (Chromium) et 2 (Firefox, Safari, Orion) sont faites, la Task 5 (interface) consommera le contrat IPC défini ici.

## Review Focus
1. Double import du même profil (fixtures Chrome « Khalil » puis Firefox « default-release ») : aucun favori ni visite dupliqué, un seul dossier « Importés de Chrome », compteurs du résultat exacts (« ajoutés / déjà présents »).
2. Historique de 100 000 visites (fixture générée par `chromium.volume.test.ts`) : lots arrivant **dans un ordre quelconque**, l'interface reste réactive (aucune tâche > 50 ms sur la boucle du main), le fichier `historique.jsonl` reste cohérent après compaction, les visites plus anciennes que `depuisJours` ne sont pas écrites.
3. Abandon par `AbortSignal` au milieu de l'historique : le processus enfant s'arrête, les copies temporaires sont supprimées, ce qui a été écrit reste cohérent (pas de ligne JSON tronquée), le résultat donne `annule` pour l'historique et les éléments suivants, les précédents restent `ok`.
4. Onglets → constellations : un groupe Chromium « Docs » (bleu) devient une constellation « Docs » de la couleur la plus proche de la palette du ciel ; un onglet sans groupe reste hors constellation ; les étoiles sont créées **endormies** (pas de chargement réseau à l'import) sauf si l'utilisateur coche « ouvrir maintenant ».
5. Moteurs : un mot-clé importé en conflit (`w` de Firefox « Wikipédia (fr) » contre `w` de Lyra) n'écrase jamais un mot-clé de Lyra, reçoit un suffixe, et le résultat le dit ; le moteur par défaut intégré de Firefox (`ddg`) devient `moteurParDefaut: 'duckduckgo'` seulement si l'utilisateur a coché « réglages ».
6. Profil absent ou élément `Indisponible` : résultat par élément avec `code`, jamais d'exception, le reste est appliqué.

## 2. Correspondances

### Favoris → dossier « Importés de <navigateur> »
- Dossier racine `Importés de ${NOMS_NAVIGATEURS[source]}` ; sous-dossiers en chemin « Importés de Chrome / Lecture / Astronomie » ; favoris de `barre` et `autres` au même niveau ; `Favoris mobiles` gardé comme sous-dossier (déjà rangé par les lecteurs).
- Dédoublonnage : `url` exacte, après normalisation minimale (suppression du fragment vide et du `/` final si le chemin est vide, jamais plus : `https://a.fr/x` et `https://a.fr/x/` restent distincts). Un favori déjà présent **ailleurs** (hors dossier d'import) n'est pas recréé ; compté « déjà présent ».
- Réimportation : le dossier existe déjà → on le complète ; jamais de « Importés de Chrome (2) ».
- Titre vide → l'URL (les lecteurs le garantissent déjà) ; `date` d'origine conservée (0 → `Date.now()`).

### Historique → fusion sans doublon
- Lots **non triés** par date (le flux Chromium groupe par page, Firefox aussi ; `parcourirHistorique*` ne trie pas) : `importer(lot)` n'a aucune hypothèse d'ordre, l'index `dates[]` n'est trié qu'à la compaction (`compacter()` réécrit d'après l'index, dans l'ordre d'insertion ; `frequents()` filtre par date, pas par position → pas d'impact).
- Clé : `(url, date ms)`. Page déjà connue sans cette date → date ajoutée ; déjà connue avec cette date → « présente ». `visites` (compteur de la fenêtre) n'est pas rejouable : rendu dans le résultat (« 18 420 visites, 1 284 pages ajoutées »), et une seule date par page écrite.
- `urlRetenue` reste la règle (http(s) seulement, `file://` sous `LYRA_TEST`) ; titres : `majTitre` si le titre importé est non vide et celui de Lyra vide.
- Fenêtre : `depuisJours` transmis au lecteur (92 par défaut, `null` = tout) ; rien n'est filtré une seconde fois côté main.
- Écriture : une ligne JSON par visite ajoutée, un seul `appendFile` par lot (`enfiler`), `attendre()` avant de rendre le résultat ; `compacterSiNecessaire()` si plus de 10 000 lignes ajoutées.

### Onglets et groupes → constellations
- Une **constellation par groupe** importé (`GroupeImporte.id` → `Constellation.id` neuf, `name` = `nom` ou, si vide, « Groupe <couleur> », `color` = couleur de `PALETTE_CONSTELLATIONS` la plus proche de `COULEURS_GROUPE[couleur]` par distance euclidienne en espace OKLab (ou RGB linéaire si trop lourd : préciser dans le code) ; même nom déjà existant dans la fenêtre cible → réutilisée, comme le design le demande (« même nom »).
- Onglets hors groupe → étoiles sans constellation ; `epingle` → `pinned: true` ; un onglet `about:`/`chrome://` a déjà été filtré par les lecteurs.
- Fenêtres : option `fenetre: 'courante' | 'nouvelle-par-fenetre'` (défaut : tout dans la fenêtre courante, dans l'ordre des fenêtres importées ; Task 5 propose « une fenêtre Lyra par fenêtre importée »).
- Étoiles créées **endormies** via `ouvrirEndormie` (titre importé affiché immédiatement, chargement au clic) ; option `ouvrirMaintenant` pour charger les 10 premières ; `sauverSession()` à la fin pour que `SessionStore` les conserve.
- Dédoublonnage : une URL présente deux fois dans la même fenêtre importée n'est créée qu'une fois ; pas de dédoublonnage contre les étoiles existantes (comportement explicite, noté dans le résultat).

### Moteurs et mots-clés
- Moteurs **intégrés** (Chromium `prepopulate_id`, Firefox `integre: true` via `lireMoteurParDefautFirefox`) : table de correspondance `src/main/import/moteurs.ts` : `google`/`google.com` → `google`, `ddg`/`duckduckgo.com` → `duckduckgo`, `bing`/`bing.com` → *(absent de Lyra : ignoré, dit dans le résultat)*, `wikipedia-fr`/`fr.wikipedia.org` → `wikipedia`, `qwant` → `qwant`, `brave`/`search.brave.com` → `brave`, `startpage` → `startpage`, `kagi` → `kagi`, `youtube` → `youtube`, `ecosia`/`yahoo`/autres → ignorés. Le **moteur par défaut** importé ne remplace `Settings.moteurParDefaut` que si l'élément `reglages` est coché **et** que `moteurChoisi` est faux ou que l'utilisateur confirme (Task 5 : case « Faire de <nom> le moteur par défaut »).
- Moteurs **perso** (`perso: true`, URL avec `%s`) → `Settings.moteursPerso` ; clé `url` normalisée pour le dédoublonnage (réimport = « présent »).
- **Arbitrage des mots-clés** : les mots-clés de Lyra (`d k g b s q w yt`) sont réservés. Conflit (insensible à la casse, après `normaliser`) → suffixe du navigateur source puis chiffre : `w` → `w-ff`, puis `w-ff2` ; conflit entre deux moteurs importés → le second reçoit le suffixe ; un mot-clé vide ou > 24 caractères → dérivé du nom (`wikipediafr`). Chaque renommage figure dans le résultat (« mot-clé `w` déjà pris par Wikipédia : devient `w-ff` »). Les mots-clés Vivaldi (point reporté de la Task 1) suivent la même règle.
- Les suggestions de la palette (`suggest.ts`) listent `moteursDisponibles(settings)` : les perso apparaissent avec leur mot-clé, sans couleur dédiée (lettre initiale, couleur `--accent`).

### Réglages transposables
- `pageAccueil` : pas de champ en v1 → résultat « sera disponible avec Démarrage et sessions » (jalon D) ; la valeur est conservée dans `Settings.import.reglagesEnAttente.pageAccueil` pour que le jalon D l'applique sans réimporter.
- `dossierTelechargement` : `patchImporte` existant (répertoire absolu existant seulement) → `telechargements.dossier` ; sinon « dossier introuvable sur cet ordinateur ».
- `langue` : `fr-FR`/`fr-*` → `fr`, `en-*` → `en`, autre → ignorée et dite.
- `zoomParSite` : hôte → origines (`https://hote`, `https://www.hote`), facteur arrondi au palier `PALIERS_ZOOM` le plus proche, écrit dans `sites[origine].zoom` par **un seul** `setSettings` (patch fusionné) ; un zoom existant dans Lyra n'est pas écrasé (noté « présent »).

### Extensions → `import.extensionsEnAttente`
- Chaque `ExtensionImportee` cochée → `{ id, nom, magasin, actif, source, date }` dans `Settings.import.extensionsEnAttente` (dédoublonnée sur `id`+`magasin`, 200 max, les plus récentes gardées).
- `magasin: 'chrome'` et `'firefox'` sont réinstallables par le plan B (`installerParId`) ; `'edge'` et `'inconnu'` restent en file avec `etat: 'manuel'` pour que `lyra://extensions` les affiche « à installer à la main ».
- Extensions **imposées par une stratégie** (Chromium `location` 7 = `EXTERNAL_POLICY_DOWNLOAD`, 9 = `EXTERNAL_POLICY`) : `imposee: true`, décochées par défaut dans l'aperçu, jamais mises en file sans action de l'utilisateur. Ce champ s'ajoute dans `types.ts` (`ExtensionImportee.imposee?: boolean`) et dans `chromium.ts` (lecture de `location`), sans toucher aux lecteurs Firefox (`location` AMO ≠ stratégie ; une stratégie Firefox passe par `policies.json`, hors v1).
- Rien n'est téléchargé pendant l'import (contrainte du plan parent).

### Cookies
- Désactivés en v1 : Chromium les chiffre par le système (DPAPI, trousseau) ; l'interface le dit (« chiffrés par le système : indisponibles ») ; aucune lecture de `Cookies`/`cookies.sqlite` n'est tentée (pas de copie inutile d'un fichier sensible).

## 3. Exécution

### Lecture dans un `utilityProcess`
- `src/main/import/processus.ts` (côté main, Electron autorisé) : `utilityProcess.fork(join(__dirname, 'import-worker.js'), [], { serviceName: 'lyra-import', stdio: 'ignore' })` ; une instance par import, tuée à la fin ou à l'abandon (`kill()`), relancée si `exit` inattendu (résultat : tous les éléments restants `Indisponible { code: 'annule', raison: 'Le lecteur s'est arrêté' }`).
- `src/main/import/worker.ts` (entrée electron-vite supplémentaire `main/import-worker`, **sans Electron**) : reçoit `{ type: 'lire', profil: ProfilDetecte, params: ParametresLecture, elements }`, appelle `lireProfilChromium` / `lireProfilFirefox` / `lireProfilSafari` / `lireProfilOrion` selon `profil.navigateur`, et, pour l'historique, `parcourirHistorique{Chromium,Firefox}` (Safari/Orion : `donnees.historique` en un lot) ; envoie `{ type: 'progression', element, fait }`, `{ type: 'lot', element: 'historique', visites }` (lots de `tailleLot` = 2 000), `{ type: 'element', element, valeur | Indisponible }`, `{ type: 'fin' }` ; reçoit `{ type: 'annuler' }` → `AbortController.abort()` (vérifié entre éléments et entre lots par les lecteurs).
- Le même `worker.ts` sert à la **détection** (`detecterProfils`) et à l'**aperçu** (`lireProfil*` avec `elements` cochés et `tailleLot`, historique en flux compté seulement : `{ pages, visites }`) : l'aperçu n'a jamais d'historique en mémoire, les compteurs viennent de `compter()` et du résumé du flux.
- Sérialisation : `postMessage` (structured clone) ; `ErreurImport` ne traverse pas → le worker convertit tout en `Indisponible` avant d'envoyer (`versIndisponible`).

### Écriture par lots dans le main, sans bloquer
- `appliquer.ts` expose `appliquer(donnees | flux, cibles, options, surProgression, signal): Promise<ResultatImport>` où `cibles` = `{ favoris: { ajouterLot }, historique: { importer, attendre, compacterSiNecessaire }, ciel: { creerConstellation, ouvrirEndormie, sauver }, reglages: { get, set }, extensions: { enfiler } }` (interfaces dans `appliquer.ts`, implémentées dans `ipc.ts` à partir de `index.ts` ; faux magasins dans les tests).
- Favoris : un seul `ajouterLot` (une écriture atomique). Historique : un `importer(lot)` par lot reçu du worker, `await pause()` (`setImmediate`) entre deux lots, `attendre()` à la fin. Onglets : création par tranches de 50 étoiles avec `pause()` et une seule `sauverSession()`. Réglages : un seul `setSettings` (patch cumulé). Extensions : un seul `setSettings`.
- Ordre d'application : favoris → moteurs → réglages → extensions → onglets → historique (le plus long en dernier, l'utilisateur voit tout de suite les favoris et les étoiles).
- Abandon (`signal`) : vérifié avant chaque lot et chaque tranche ; ce qui est écrit reste (pas de rollback : `JsonStore` et `appendFile` sont atomiques par écriture) ; éléments restants `annule`.

### Démarrage
- `index.ts` (ajout localisé, après `creerReglages`) : `void balayerOrphelins({ dossierTemp: app.getPath('temp') })` à l'`app.whenReady`, résultat journalisé ; jamais bloquant.

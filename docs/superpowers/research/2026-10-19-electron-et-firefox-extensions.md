# Recherche — extensions Chrome natives dans Electron 44 et extensions Firefox (.xpi)

Agent de recherche, 2026-10-19 (sources : electron.d.ts 44.9.0, docs Electron, README electron-chrome-extensions 4.9.0, MDN, doc API AMO, dépôts GitHub des extensions).

## A. Electron 44.9.0 (Chromium 152) — support natif

- API : `session.extensions.loadExtension(path, { allowFileAccess })`, `removeExtension`, `getExtension`, `getAllExtensions` ; événements `extension-loaded` / `extension-unloaded` / `extension-ready`. Dossiers décompressés seulement (`.crx` refusés) ; session persistante obligatoire ; rien n'est mémorisé entre lancements (recharger à chaque démarrage, avant la création des vues). Les anciennes `ses.loadExtension`… sont dépréciées.
- Clés de manifest reconnues (doc) : name, version, author, permissions, content_scripts, default_locale, devtools_page, short_name, host_permissions (MV3), manifest_version, background (MV2), minimum_chrome_version.
- API chrome.* natives : complètes `scripting`, `webRequest` (le `session.webRequest` d'Electron prend le pas : **un listener Electron neutralise les listeners d'extension**), `devtools.*` ; partielles `runtime`, `tabs` (sendMessage, reload, executeScript, query, update), `storage` (`local` seul), `management`, `extension`. Absentes : `action`/`browserAction`, `contextMenus`, `windows`, `cookies`, `webNavigation`, `notifications`, `declarativeNetRequest`, `commands`, `i18n`, `storage.sync`. Les API non listées sont « provisoires ».
- MV3 (service workers) : correctif Electron PR 39290 (2023) ; Electron 35 a ajouté `registerPreloadScript` et `ServiceWorkerMain.ipc` pour les extensions MV3 ; **non vérifié sur 44.9.0** (à prouver par le spike). MV2 : Chrome a désactivé MV2 en 138 et retire le code ; la doc Electron 44 garde `background` MV2 — **à tester** (le spike uBO Chromium MV2 tranche).
- `electron-chrome-extensions` 4.9.0 (Electron ≥ 35.0.0-beta.8, licence GPL-3.0 ou Patron, `sandbox: true` requis pour le preload) ajoute : `action` (sauf enable/disable), `contextMenus` (sans update), `cookies` complet, `notifications` (sans onButtonClicked), `storage.sync`/`managed` → local, `windows` complet, `webNavigation` partiel ; `tabs` sans duplicate/highlight/move/captureVisibleTab/discard ; `commands` non supporté ; pas d'extensions en session non persistante ou privée ; « all background scripts are persistent ». Constructeur `new ElectronChromeExtensions({ license, session, createTab, selectTab, removeTab, createWindow, removeWindow, requestPermissions, assignTabDetails })`, `extensions.addTab(webContents, browserWindow)` par onglet.
- `BrowserView` déprécié → `WebContentsView` ; `webContents.goBack`… dépréciés (v32) → `navigationHistory` ; `setWindowOpenHandler` avec `createWindow` pour ouvrir dans une WebContentsView.

## B. Extensions Firefox

- XPI = zip ; signature dans `META-INF/` (manifest.mf, mozilla.sf, mozilla.rsa, cose.sig) : à supprimer après extraction, Chromium ne la vérifie pas.
- AMO v5 : `GET https://addons.mozilla.org/api/v5/addons/addon/<slug|id|guid>/` → `current_version.file.url`, `.hash` (`sha256:`), `permissions[]`, `host_permissions[]` ; recherche `/api/v5/addons/search/?q=…&app=firefox` ; limites de débit non documentées (cacher localement par version + hash).
- Différences de manifest : `browser_specific_settings`/`applications` (à retirer) ; Firefox n'a pas `background.service_worker` (exécute `scripts`), Chrome MV3 ignore `scripts` depuis 121 → générer un service worker ; `browser_action`/`page_action` → `action` en MV3 ; `sidebar_action` ≠ `side_panel` (pas de support Electron) ; CSP chaîne (MV2) → objet `{extension_pages}` (MV3, seuls 'self' 'none' 'wasm-unsafe-eval') ; `web_accessible_resources` chaînes → `[{resources, matches}]` ; `incognito: split` non géré par Firefox ; permissions Firefox-only (`contextualIdentities, menus→contextMenus, find, pkcs11, dns, captivePortal, browserSettings, tabHide, publicSuffix, webRequestFilterResponse`) à retirer avec journal ; `protocol_handlers, theme_experiment, experiment_apis, dictionaries, user_scripts, developer` à retirer ; séparer `permissions` / `host_permissions` ; icônes SVG à convertir en PNG (supposé) ; `key` pour un ID stable.
- **Espace de noms `browser` natif dans Chrome depuis 148** (MDN, README du polyfill ; exception DevTools levée en 152) → Chromium 152 d'Electron 44 l'a sans doute : à vérifier dans le spike ; `webextension-polyfill` 0.12.0 (MPL-2.0, 9,9 Ko min) est archivé depuis 2026-07-30 ; il refuse de s'installer hors contexte d'extension et devient neutre si `browser.runtime.id` existe. À garder seulement en secours.
- Orion (Kagi) : implémente lui-même ~70 % des API WebExtensions, installe depuis les deux stores, annonce honnêtement les manques.
- Cas concrets : uBlock Origin Firefox = MV2 + `webRequestBlocking` + `sidebar_action` → **non convertible** (le blocage est assuré par les Boucliers de Lyra ; la version Chromium MV2 de uBO est le test clé du spike) ; Dark Reader → build Chrome MV3 préférable au xpi ; Bitwarden → build Chrome MV3 (messagerie native inopérante) ; Tree Style Tab → non (sidebar, tabHide, contextualIdentities) ; Privacy Badger → non (webRequestBlocking MV2) ; SponsorBlock, Return YouTube Dislike → convertibles avec réécriture MV3 (supposé).

## Conséquences pour Lyra

1. Le support « Chrome » passe par Electron natif + electron-chrome-extensions (GPL-3.0 pour Lyra) ; **le blocage réseau reste celui des Boucliers** (session.webRequest), une extension bloqueuse ne fera pas mieux et ses listeners webRequest seront neutralisés : le dire dans le journal de compatibilité.
2. Le support « Firefox » = convertisseur xpi → dossier Chrome MV3 strictement réglé, avec rapport JSON (clés supprimées/réécrites, API retirées) et refus motivé si `webRequestBlocking`, `sidebar_action` seul, ou `background.page` MV2 sans équivalent. Privilégier le build Chrome officiel de l'auteur quand il existe (détection par le même nom sur le Chrome Web Store).
3. Questions à trancher par le spike : MV2 `background.page` sur Electron 44 ? service worker MV3 ? `browser` natif ?

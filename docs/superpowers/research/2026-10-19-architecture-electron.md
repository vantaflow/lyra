# Recherche — architecture d'un navigateur Electron 44 pour Lyra

Agent de recherche, 2026-10-19 (docs Electron, code de Min 1.35.7, electron-browser-shell 2.2.0, Peersky ; paquets electron-vite 6.0.0 et electron-context-menu 5.1.0 lus après npm pack).

## Vues et fenêtre
- `BaseWindow` + `WebContentsView` : une vue **chrome** (ciel + capsule), une vue par onglet (une seule attachée/visible), une vue **overlay** transparente ajoutée en dernier (palette ⌘ L, popups d'extension) — un WebContentsView enfant se dessine toujours au-dessus des autres, donc un overlay HTML dans la vue chrome ne peut pas passer au-dessus d'une page. `setBackgroundColor('#00000000')` (format AARRGGBB) pour la transparence ; `addChildView` sur un enfant existant le remonte au sommet ; pas d'auto-resize : recalculer les bounds sur `resize` et au changement de position du ciel ; fermer un BaseWindow ne détruit pas les webContents des vues (les fermer soi-même). Fenêtre enfant transparente écartée (déplacement, focus, plein écran).
- Plein écran HTML : `enter/leave-html-full-screen` → onglet plein cadre, chrome et overlay masqués.
- Onglets inactifs : `setVisible(false)` (shell) ou `removeChildView` (Min) ; aucun « discard » natif : **dormance = `webContents.close()` puis recréation avec `navigationHistory.restore({entries, index})` avant le premier `loadURL`** ; `setBackgroundThrottling(false)` affecte toute la fenêtre (ne pas l'utiliser).
- Popups : `setWindowOpenHandler` : sans `features` = clic de lien → `deny` + nouvel onglet relié au parent ; avec `features` (OAuth) → `allow` + `createWindow(opts) => new WebContentsView({ webContents: opts.webContents }).webContents` (pattern Min). Electron 44.9.0 corrige l'héritage de session/webPreferences de l'opener.
- Événements à relayer : `will-navigate` (pas les navigations programmatiques ni in-page), `will-frame-navigate`, `did-navigate`, `did-navigate-in-page`, `page-title-updated`, `page-favicon-updated`, `did-fail-load`, `did-change-theme-color`, `render-process-gone`, `did-start/stop-loading`.

## Permissions, notifications (Ne pas déranger), téléchargements
- `setPermissionRequestHandler` et `setPermissionCheckHandler` **ensemble** ; le check reçoit `webContents: null` pour `notifications` et les service workers → décider par `requestingOrigin`.
- **Aucune API Electron n'intercepte `new Notification()`** côté main. Ne pas déranger = (1) refuser `notifications` dans les handlers = « denied » mémorisable par les sites (pas du « retenu ») ; (2) surcharger `window.Notification` dans le monde principal via un preload de session (`ses.registerPreloadScript({type:'frame'})` + `contextBridge.executeInMainWorld({func,args})`, expérimental ; `func` sérialisée, canal retour par `exposeInMainWorld`), file d'attente rejouée à la sortie ; alternative CDP `debugger` + `Page.addScriptToEvaluateOnNewDocument` ; (3) notifications de service worker / push : **aucun hook trouvé** (question ouverte). Sur macOS, Electron ≥ 42 : une app non signée n'affiche aucune notification (`UNNotification`).
- `session.on('will-download', (e, item, wc, frame))` par session (défaut, `persist:*`, privée) ; `DownloadItem` : setSavePath, pause/resume/cancel, getURLChain, `updated`/`done`.
- `findInPage` / `found-in-page` / `stopFindInPage` ; zoom `setZoomFactor` (0.25-5), `setZoomMode('isolated')` ; persistance du zoom par site à faire dans SiteRules.
- Raccourcis : `Menu` + accélérateurs, et `before-input-event` + `preventDefault()` sur chaque onglet pour les touches que la page ne doit pas avaler (⌘ L).
- `electron-context-menu` 5.1.0 : ESM seul, Node ≥ 24, à appeler `contextMenu({ window: view })` **par onglet** (sans option il n'écoute que `browser-window-created`), `dispose` à la fermeture ; tire `electron-dl` (conflit possible avec `will-download`, à tester) → alternative : écouter `context-menu` soi-même avec `params` (misspelledWord, dictionarySuggestions…).
- Protocole `lyra://` : `protocol.registerSchemesAsPrivileged([{ scheme:'lyra', privileges:{ standard, secure, supportFetchAPI, codeCache } }])` avant `ready` (un seul appel) ; `ses.protocol.handle('lyra', req => net.fetch(pathToFileURL(file)))` **par session** (`app.on('session-created')`), garde anti-traversée (`path.relative`, rejet de `..`) comme Min.
- Thème : `nativeTheme.themeSource` ('system'|'light'|'dark') pilote `prefers-color-scheme` ; `did-change-theme-color` pour la teinte du site ; thèmes = variables CSS poussées par IPC.
- Session : `getAllEntries()` + `getActiveIndex()` sauvegardés ; `restore` avant `loadURL`. PDF : rendu OOPIF dans le même WebContents depuis Electron 41. UA : `ses.setUserAgent(ua, acceptLanguages)` sans « Electron/x » (client hints Sec-CH-UA non vérifiés). Spellcheck : automatique sur macOS, `setSpellCheckerLanguages` ailleurs. macOS 13 minimum.

## Outillage
- electron-vite 6.0.0 (Vite 8 / rolldown ; config statique, plus de fonction ; `externalizeDeps` actif par défaut) : plusieurs preloads et pages via `build.rollupOptions.input` ; `isolatedEntries: true` + `externalizeDeps: false` pour des preloads sandbox autonomes ; **pas de `"type":"module"`** (sinon preloads en `.mjs`, non supportés en sandbox) ; en dev `process.env.ELECTRON_RENDERER_URL` + `/ui.html`.
- Framework UI : **Preact 11.0.1** + `@preact/preset-vite` 2.10.6 (petit VDOM, hooks/signaux, `preact/compat`) — React/Solid/Svelte/Lit écartés (pas de gain décisif) ; mesurer la taille au premier build.
- `electron-chrome-extensions` 4.9.0 : GPL-3.0 ou licence Patron → Lyra en GPL-3.0.

## Modules recommandés (main)
WindowManager (BaseWindow, vues chrome/overlay, relayout selon la position du ciel, plein écran, Ne pas déranger) · TabManager (arbre parent/enfants/constellations, WebContentsView, activation, fermeture, dormance close+restore, popups reliées, relais des événements) · Shields (session.webRequest + CSP + preload scriptlets, règles par site) · ExtensionsManager · Settings / SiteRules (JSON) · History / Bookmarks · Downloads · Dnd · Protocol (lyra://) · Permissions. Preloads sandbox CJS : `ui`, `internal` (pages lyra://), `page` (sites : Shields + Notification), `ext`. Renderer Preact : `ui.html` (ciel, capsule, overlay par route), `newtab.html`, `settings.html`, `extensions.html`. IPC typé : `ipcMain.handle` + `webContents.send`, vérification de `event.senderFrame.url` dans chaque handler, table de canaux partagée `src/shared/ipc.ts`.

## Risques
Notifications (pas d'API ; surcharge contournable ; push non couvert) · signature macOS requise pour les notifications · overlay plein fenêtre capte les clics (fermeture au clic extérieur, focus) · dormance perd l'état non sérialisé (vidéo, formulaires, WebSocket) · licence GPL · electron-context-menu ESM/electron-dl · API expérimentales (`executeInMainWorld`, `isolatedEntries`) · ne pas exposer de fonctions async inutiles aux pages (GHSA-h7rp-cf8h-j98x, corrigé avant 44) · Wexond abandonné, Peersky en `<webview>` : seuls Min et electron-browser-shell sont des références WebContentsView.
